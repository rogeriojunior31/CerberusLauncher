# Page review: Cerberus vs Hydra, RecompLauncher and Playnite

One agent per page compared Cerberus with the three references (23/11/2026). Priority 1 = must, 2 = should, 3 = nice. RecompLauncher is GPL: ideas only.

## News (Novidades) - ui/src/news.rs

Novidades works, but it is an activity log, not a news page. It has a plain text line for "no updates" and a flat list of the last 40 history entries (trail.recent(40) in src-tauri/src/main.rs:1900). The list has no art, no day grouping, no unread state, no filters and nothing to dismiss, and it repeats rows: the same SpaghettiKart crash appears twice, and every session also writes a "Backup depois de jogar" row. RecompLauncher's "What's new for your games" shows release notes as cover cards, Hydra's Notifications page has unread/all tabs with mark-read and dismiss, and Playnite's notification panel merges entries by id. Compared with those, Cerberus today shows the least useful information of the four, even though it already has richer local data (Steam news without a key, recomp release notes, achievements with rarity, play time) to fill the page.

### Missing

- **P1 Release notes for the player's recomps ("What's new for your games")** (M). Each installed recomp's last 1-3 releases from the past ~60 days shown as cards: cover, game name, release title/tag, date, an "Installed" or "Ready to update" tag, and the first 2 lines of the notes. Click opens the game's Updates tab with those notes expanded. The player can see what changed before updating. Today "Ver o que mudou" only goes to the game page, and shared::Release has no notes or date fields (shared/src/lib.rs:811). _Refs:_ RecompLauncher src-tauri/src/lib.rs:7832-7885 (news_for: 60-day cutoff, take(3) per repo, truncate 10), ui/app.js:1734-1746 (newsSection, notesLine), ui/app.css:295-304 (.news-grid/.news card). _Data:_ GitHub/GitLab/Forgejo releases API that Cerberus already queries for the recomp catalog (body, published_at, name, html_url). Cache on disk like RecompLauncher's releases_on_disk.
- **P1 Steam news and patch notes for installed or recently played Steam games** (M). Official patch notes and announcements (title, date, feed, image, excerpt) for the games the player actually has. This is what turns the page into real news, and it is the biggest gap. Limit it to installed games or those played in the last N weeks, and show the newest 10-20. _Refs:_ None of the three has it (Hydra relies on its own server; Playnite's equivalent comes from add-ons). Steam client Library 'What's New' shelf is the model.. _Data:_ Steam Web API ISteamNews/GetNewsForApp/v2 (no key needed; appid, count, maxlength, feeds=steam_community_announcements). Images come from the Steam clan CDN URLs found in the contents.
- **P1 Unread state, mark all as read, dismiss** (S). Things that happened since the player's last visit stand out (accent left border, full opacity). Already-seen items fade. There is a "Marcar tudo como lido" button and an x on each row. The sidebar bell badge should count unread items, not just pending updates. _Refs:_ Hydra src/renderer/src/pages/notifications/notifications.tsx (handleMarkAllAsRead, handleDismiss, unreadCount), notification-item.scss (&--unread border-left 3px, opacity .4 when read); Playnite PART_ButtonDismissAll in Themes/Desktop/Default/Views/NotificationPanel.xaml. _Data:_ Local: store a last_seen timestamp (and dismissed ids) in Cerberus settings. Trail entries already have `at`.
- **P1 Merge repeated events (dedupe by key)** (S). A play session, its backup, and repeated identical crashes become one row: "SpaghettiKart: Partida de 3 min, backup de 8 arquivos" or "fechou com erro (2x)". Playnite replaces a notification that has the same id instead of adding a new one. _Refs:_ Playnite source/Playnite/ViewModels/MainViewModelBase.cs:517 and :716 (Notifications.Add/Remove with stable ids like "{plugin.Id} - import"); PlayniteSDK/INotificationsAPI.cs. _Data:_ Local trail: group by game_id plus step within a time window, and fold "Backup depois de jogar" into the preceding "Partida".
- **P2 Filter tabs (Tudo / Não lidas / Conquistas / Problemas)** (S). Lets the player find the crash or the achievement without scrolling through backup rows. Hydra uses All/Unread tabs with a count badge and an animated underline. _Refs:_ Hydra notifications.tsx renderFilterTabs, notifications.scss &__filter-tabs/&__tab-badge/&__tab-underline. _Data:_ Local trail: filter on step and ok.
- **P2 Day headers (Hoje / Ontem / date)** (S). Players can scan the timeline by day. Today every row repeats "ontem"/"há 3 dias" in the right column. _Refs:_ RecompLauncher ui/app.js (Downloads Recent: 'The day a download finished, for Recent's day headers: today, yesterday, else the date', around lines 4632-4720). _Data:_ Local trail `at`.
- **P2 Achievement unlock entries with icon and rarity** (M). An achievement row shows its badge icon, name and global rarity ("3.2% dos jogadores") instead of a generic trophy glyph, which makes the news feel rewarding. Hydra shows ACHIEVEMENT_UNLOCKED local notifications with a picture. _Refs:_ Hydra pages/notifications/local-notification-item.tsx (pictureUrl, TrophyIcon), notification-item.tsx RETROACHIEVEMENTS_* cases. _Data:_ Steam GetSchemaForGame icons plus GetGlobalAchievementPercentagesForApp, and the RetroAchievements API badge URL. Steam local achievement cache works without a key for detection.
- **P2 Launcher's own changelog after Cerberus updates ("O que há de novo")** (S). A card at the top the first time a new Cerberus version opens. It counts changes and fixes ("12 mudanças · 4 correções"), shows the first few, and has a link to the full changelog. Playnite's UpdateWindow lists the notes of every version between the installed one and the newest, not only the latest. _Refs:_ RecompLauncher ui/app.js:7735-7790 (noteItems, updateStart with from->to jump and counts), ui/app.js:4863 (whats_new_off setting); Playnite source/Playnite.DesktopApp/Windows/UpdateWindow.xaml (ItemsNotes bound to ReleaseNotes list). _Data:_ Cerberus's own GitHub releases.
- **P3 Update all** (S). A single action when two or more recomps are behind. _Refs:_ RecompLauncher Downloads page (updates ready section, ui/app.js ~4650). _Data:_ Local: loop over discover::start_install.
- **P3 Library changes: new games found, uninstalled games** (M). "3 jogos novos encontrados na Steam", "Epic: Hades instalado", so the player sees what the scan picked up. Playnite raises import results and errors as notifications. _Refs:_ Playnite source/Playnite.DesktopApp/ViewModels/DesktopAppViewModel.cs:681-728 (ImportedGames), MainViewModelBase.cs:517 (import errors as notifications). _Data:_ Local: diff of the Steam and Epic scans between runs, written to the trail.
- **P3 Free Steam sales/discounts for wishlisted or owned games** (L). Would tell the player about price drops, but it is not a launcher concern and Cerberus has no wishlist data without a server. _Refs:_ None. _Data:_ needs server (or the Steam store wishlist endpoint with a login cookie, which is not appropriate). Skip.

### Ugly or unfinished

- The 'Atualizações disponíveis' section takes ~150px for a single grey sentence ("Todos os seus recomps estão na versão mais nova.") followed by a large empty gap before the next section. It is the most prominent block on the page while it has nothing to say. **Fix:** When there are no updates, collapse the section into a small inline status chip in the header (check icon plus "Recomps em dia"). Show the full section only when updates exist, as a highlighted card row with an "Atualizar todos" button.
- The activity list rows have no art. Every row is the same green check plus bold "Game · Step". With 40 near-identical rows, the eye has no anchor and the game cannot be recognised at a glance. **Fix:** Put a 40x56 cover (Poster with cover_sources) or a square game icon at the left of each row, as Hydra's 48px notification-item__picture does, and move the status to a small badge on the cover corner (green check, red !, gold trophy).
- Noise: each session creates 2 rows (Partida plus Backup depois de jogar), and a "0 min jogados" or "6 s jogados" session gets a full row. The same crash appears on two different days with the same long message. **Fix:** Fold the backup into the session row as a sub-line ("3 min · backup de 8 arquivos"). Hide sessions under 1 minute, or merge them into "aberto rapidamente". Collapse identical errors into one row with a count ("2x esta semana").
- The error rows print a raw, truncated Windows path in the message ("Log do jogo: C:\Users\..."). It is cramped, unreadable and leaks a path into a news feed. **Fix:** Show a short reason ("Travou: acesso inválido à memória") and put the log behind a "Ver log" or "Abrir pasta" button. Give the row a red-tinted left border instead of relying only on the small red icon.
- The relative time is at the far right, about 950px from the title, and repeats "ontem"/"há 3 dias" on many rows. Rows are 66px tall with the title and description close together, while the time floats at mid-height. **Fix:** Add day headers (Hoje / Ontem / 18 nov) and show only the clock time (14:32) under each header. Keep the time next to the title or right-aligned with the title baseline, not vertically centred.
- The content is capped at 980px (.news-sec max-width in ui/styles.css:1078) on a 1918px window, which leaves ~640px of empty black to the right. **Fix:** Use a two-column layout at ≥1400px. The left/main column (~2fr) holds the game news (recomp release notes and Steam news cards). The right rail (~1fr) holds Atividade (compact timeline) and a 'Esta semana' summary (hours played, achievements unlocked, games opened).
- Loading state is a plain "Carregando..." text, and the list has no limit control or "ver mais". Recent activity hard-stops at 40 with no way to see older entries. **Fix:** Show 4-6 skeleton rows of the same height as real rows so nothing jumps, and add a "Carregar mais" button that pages the trail (Hydra notifications.tsx load-more pattern).
- The empty state for activity is one muted line with no icon or action. **Fix:** Use a centered empty state like Hydra's: a 60px round icon container with a bell icon, a title ("Nada novo por aqui"), a line of explanation, and a button to the Biblioteca or Descobrir.
- Clickable rows look exactly like non-clickable ones (only the class .clickable changes the hover). Nothing says that a row opens the game, and the rows are <li> with on:click, so they cannot be reached with Tab or a controller. **Fix:** Render clickable rows as <button>s (Hydra uses a button for notification-item) with a chevron on the right on hover, and keep a focus ring for keyboard and controller navigation.
- The step label is the raw trail word ("Jogar clássico", "Instalação") joined with a dot, so the title reads like a log line ("MHGU Recomp · Instalação"). **Fix:** Write sentence-style titles per step: "MHGU Recomp instalado (v0.18.3)", "Você jogou SpaghettiKart por 3 min", "Conquista desbloqueada em ...".

- The Recent list is grouped under day headers, and each game appears once with its newest event and a quiet 'i' button for patch notes. (RecompLauncher ui/app.js ~4616-4720 (Downloads Recent: day headers, dl-notes button)). **Adapt:** Group trail entries by local day and show each game's events in one compact row per day, with a small notes or 'i' button when the game is a recomp with releases.

### Proposal

NOVIDADES - target layout (1918 wide: main column plus right rail; below 1400px a single column with the rail stacked after the main column)

1. Header row
   - h1 "Novidades" with a one-line subtitle.
   - Right side: an "Atualizações" status chip ("Recomps em dia" green, or "2 atualizações" accent and clickable to scroll), then "Marcar tudo como lido".
   - Under it, filter chips: Tudo | Não lidas (n) | Atualizações | Notícias | Conquistas | Problemas. The chips render immediately, before the data arrives.

2. Updates banner (only if updates exist; otherwise nothing, the chip covers it)
   - A card with a header ("2 recomps com versão nova") and an "Atualizar todos" button.
   - One row per recomp: cover 48x64, name, "v0.18.3 → v0.19.0 · 4 mudanças · 2 correções", buttons "Ver o que mudou" (drawer with all notes from→to) and "Atualizar" (fills with progress in place).

3. MAIN COLUMN, "Para os seus jogos" (news feed, sorted by date, unread first)
   - Card types in one 2-column grid (1 column when there is one item):
     a) Recomp release: cover, game kicker, release title, date plus Instalada / Pronta para atualizar, a 2-line notes excerpt. Click opens Game > Atualizações.
     b) Steam news: header image (or cover), game kicker, title, date plus feed (Patch notes / Anúncio), 2-line excerpt. Click opens a reader drawer with an external link.
     c) Cerberus itself (first open after an update): "Cerberus 0.x.y chegou", change and fix counts, first 3 items, a link to the changelog. Dismissible.
   - Unread cards have an accent left border; read ones are dimmed to about 70%. Each has a dismiss x on hover.
   - Loading: 4 skeleton cards. Empty: icon plus "Nenhuma notícia dos seus jogos nas últimas semanas" plus a button to the Biblioteca.
   - Offline or Steam news failure: a small inline "Não foi possível buscar as notícias da Steam" with Tentar de novo. The rest of the page still renders.
   - "Carregar mais" at the end.

4. RIGHT RAIL, top: "Esta semana" summary
   - 3 stat tiles: time played (with the top game), achievements unlocked (with the rarest one and its %), games opened.
   - Data: trail sessions and the achievement caches.

5. RIGHT RAIL, below: "Atividade" timeline (compact)
   - Day headers: Hoje / Ontem / 18 nov.
   - Rows: a 32px cover with a status badge (check / ! / trophy), a sentence title ("Você jogou SpaghettiKart · 3 min, backup feito"), and a clock time.
   - Merges a session with its backup, collapses repeated crashes ("Fechou com erro · 2x"), hides sessions under 1 minute.
   - An error row offers "Ver log" instead of a raw path. An achievement row shows the badge icon and rarity.
   - The rows are buttons with a focus ring and a chevron on hover, and open the game page.
   - Loading: skeleton rows. Empty: "Instalações, partidas e conquistas aparecem aqui."
   - "Ver mais" pages the trail beyond 40.

6. State and behaviour
   - last_seen and dismissed ids live in settings. Leaving the page marks everything as read.
   - The sidebar bell badge shows updates plus unread news.
   - Steam news is cached per appid for about 6h. Recomp release notes come from the cached release JSON that the update check already fetches; this needs Release to gain notes, date, title and url in shared/src/lib.rs.
   - Rows enter with a staggered animation (30ms, at most 10 items) that respects prefers-reduced-motion.

## Home (Início): ui/src/home.rs, ui/src/tiles.rs, styles in ui/styles.css (.slider, .sl-*, .shelf, .track, .tile)

Cerberus Home is a clean copy of RecompLauncher's layout (banner, then shelves), and the banner looks good. Underneath it is thin. The "Continue jogando" slide has no description, play time, achievement progress or logo, and the subtitle just says "Recomp". "Jogue de novo" shows four covers and leaves the right half of a 1918px screen empty, and the arrows next to it scroll nothing. Below the fold there are only catalog rows. RecompLauncher's Home does more for the player (quick-play on covers, Favorites, Recently updated, news for your games, a "Found in your folders" callout, page counter, game logos), and Playnite adds library-driven views (Most Played, completion status, random pick) that Cerberus can build from data it already has.
